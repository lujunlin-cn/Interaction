Stateful mechanic adapters (inventory, clue and relationship) produce typed proposals; QTE produces a deterministic timed request. StateManager / atomic world+drama commit remains authoritative. No Skill receives database write authority. Disabling a mechanic must not fabricate a successful state change. Direct adapter calls must obey the same fail-closed contract as the arbitration path; otherwise unit-level invocation can produce proposals that live Runtime would reject.

## Split / merge decisions

- Split capability policy/schema from Runtime orchestration: Understand Free Action, Evaluate Choices and Reconcile Mechanics own contracts, failure rules and evaluation. Runtime owns scheduling/commit.
- Merge competing mechanic validation into one group arbitration boundary; inventory/clue/relationship remain independently typed effect adapters. Do not add three independent interpretation calls over the same action.
- Context projection, exact duplicate filtering and reference selection are deterministic supporting tools. They are **not** new reasoning Skills.
- Narrative rendering and Production planning remain existing roles; visual_focus is a strengthened contract, not another critic call.
- Defer Evidence-bound Knowledge and mandatory Narrative Critic: current truth guard does not prove semantic entailment; independent labels required.

## Registry and routing gaps

- `intent-reconciliation` emits one span for an optional preview and another for packet creation. Both carry the same `skill_id`; without a stage field, invocation and latency metrics over-count ambiguous turns.
- `choice-evaluation` labels the Jev rank span but candidate generation is emitted as `director.candidates`; the registry capability therefore has no complete candidate→rank causal chain in the Observatory.
- `mechanic-arbitration` records disabled/rejected triggers inside its group span, while adapter spans are emitted only for successful proposals. Proposal counts are not trigger counts, and per-adapter failure rates are lower bounds.
- `mechanic.invoke()` records the first NPC in its `input.npc` summary even when the trigger names another target. This is trace corruption, not gameplay state corruption; use the trigger target for future audits.
- qte, h3-production, video-assembly and scenario-authoring are registry entries without a full `CAPABILITY_CONTRACTS` block. This is acceptable for deterministic/provider tooling, but the Developer Observatory must not imply the same evaluation guarantees as versioned reasoning capabilities.

## Measurement limits

Historical considered-skills, false-positive/negative labels and per-Skill token attribution are absent. Counts 13/13/8 cannot establish under- or over-triggering. New decision traces explicitly record considered/proposed/disabled/deduplicated/rejected, but only after the current code path runs. A proposal is not committed until the linked canonical event exists. Observatory displays a bounded observation window, not lifetime totals. Any future trigger-precision report must include attempted triggers, not just successful adapter spans.
